# LR Model Output Mismatch Investigation
**Date:** 2026-11-01  
**Trigger:** Prod LR briefs (2026-11-01 12:53 [lr] and 21:27 [lr]) did not match `compare_lr_vs_keyword.py` experiment results.

---

## Summary

The weights are **not being lost** in the current code. The "fresher experiment" is largely a **look-ahead artifact** (the experiment sees items published after its own `--date`). The "unrelated DOSA items" come from **cluster assignment mechanics**, not a stale cache.

Two real bugs were found, but neither is the main cause of the reported symptoms.

---

## Finding 1: Freshness Gap = Experiment Look-Ahead

### What the experiment does
- `compare_lr_vs_keyword.py` runs `node ranker/cli.js select --date 2026-10-29`
- The LR sampler uses `now = 2026-10-29T12:00:00Z` for age and freshness
- **No date filter on the candidate pool** – 477 of 3418 pool items were published *after* 2026-10-29T12:00Z (latest: 2026-11-01)
- `pool.py::_age_days` and Node both clamp: `age = max(0, now - published)`, so every future item gets `age_days = 0`

### Quantified leak
| LR picks (3 seeds, 180 total) | Count | % of picks |
|---|---|---|
| Published after experiment's `now` | 74 | 41% |
| Greedy (5 picks) | 3 | 60% |
| Explore (25 picks) | 7 | 28% |
| Reserve (150 picks) | 64 | 43% |

### Age comparison (explore picks only)
| Source | Median age | Mean age |
|---|---|---|
| Experiment (all 25) | 2.33 | 7.61 |
| Experiment (future excluded, n=18) | 8.33 | 10.57 |
| Prod brief 21:27 (10 items) | 5.00 | 5.90 |

**With the leak removed, the experiment is older than prod.** The "fresher experiment" claim is inverted.

### Second leak in experiment
- `training_examples` table has no date cutoff
- Model is trained on labels up to 2026-11-01 (visible in `train_set.balanceByMonth`)
- Experiment's AUC/logLoss are therefore optimistic

## Finding 2: DOSA-Labelled Neuro Brief = Cluster Assignment, Not Stale Cache

### Cluster assignment
- Every pool item assigned to nearest cluster medoid by cosine distance
- **No distance threshold** – items are assigned even if far from all medoids
- Label shown in brief = medoid title of assigned cluster

### Psychedelics item (`e83879799b86`)
- Distance to C0 (DOSA medoid): 0.450
- Distance to C3 (Mosaic neuromorphic): 0.456
- Pool-wide nearest-medoid distance: p50 = 0.30, p90 = 0.42
- This item is an outlier (0.45 > p90) but still gets a **core primary slot** because round-robin picks from core clusters

### Cluster population imbalance
| Cluster | Medoid | Core | Pool items assigned |
|---|---|---|---|
| 0 | DOSA (ps:3) | yes | 151 |
| 1 | Gemmini (ps:7) | yes | 424 |

Small generic medoids (C6, C9) act as catch-alls. C6 gets 28% of the pool.

### Cluster IDs are not stable
- Cluster indices come from `wardCut` positional output
- They change when inputs change
- `fit_key` changed between 06:10Z runs (`2453cf…`) and 13:27Z run (`a470f4…`) – both `inputs` and `trainingExamples` parts changed
- Brief 29 (04:53Z) stored `cluster: 0` but we cannot confirm it meant DOSA at that time (no verbose log for that run)

## Finding 3: "Weights Lost" – Not Reproduced

### Cache round-trip is exact
- Stored `interests` vs freshly recomputed medoids: max abs diff = 0
- No NaN distances from stored `vec` objects (JSON round-trip keeps index-keyed arrays, `dot()` works)
- Cluster assignment matches for **all 3418 pool items** (stored vs fresh = 0 mismatches)

### ranker_state is consistent
- `fit_key`, `fit_parts`, `model`, `interests` all written together at 2026-11-01 13:27:57
- `model`: 119 features, all finite weights, precisions
- Weights round-trip through `toJSON`/`fromJSON` (unit test verifies predictions match)
- Current `brief.py` and `LREngine` only pass `sampling`/`desks` overrides – they do not touch model config

### Real risk (latent)
- `ranker_state` is a **single slot** – every `ensureFitted(persist:true)` overwrites it
- Callers that persist: `select`, `pool`, `refit`, `inspect`
- `cmdSelect` applies `--set` **before** fitting, so any override touching `interests`/`model`/`features` would replace the production model
- Not what happened here, but a structural fragility

## Other Bugs Found

1. **`store.js` liked cutoff broken**  
   SQL: `WHERE b.date >= ?` bound to integer `maxLikedDays=100`  
   SQLite: `'2026-10-30' >= 100` → `TRUE` (TEXT > INTEGER)  
   Effect: all liked items included regardless of age (latent – current liked items are all within 100 days)

2. **Brief `meta.epsilon` misreports**  
   Writes keyword engine's `selection.epsilon=0.25` even for LR runs (LR uses `sampling.epsilon=0.8`)

## Suggested Fixes

### Priority 1: Fix the experiment (this addresses the freshness gap)
- Filter pool to `published <= date` in `PoolProvider.load`
- Cut training rows at `date` in `store.getTrainingRows` (or pass cutoff to SQL)
- Re-run comparison; expect freshness gap to shrink or reverse

### Priority 2: Add distance threshold for cluster membership
- Items above threshold → unassigned/side pool
- Show distance in brief for traceability

### Priority 3: Store medoid ID (not cluster index) in `stories`
- Makes old briefs traceable after refits

### Priority 4: Fix liked cutoff
- Compute cutoff date in JS: `date = new Date(Date.now() - maxLikedDays*864e5).toISOString().slice(0,10)`

### Priority 5: Key ranker_state by fit_key
- Prevent experiments from overwriting production state
- Or stop persisting from non-prod callers
